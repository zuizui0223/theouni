# Theory Universe v0.5.1 — semantic clarification patch

Status: **current semantic clarification layer over the immutable v0.5 core**.

This patch does not replace or rewrite the frozen v0.5 files. It narrows two ambiguous readings that could otherwise create apparent contradictions when the theory is connected to empirical work:

1. the distinction between the **evidence/reliability requirement declared by a scientific contract** and a **realized evidence class after an observation**;
2. the meaning of `LossResponseSignature`, which must be **contract-complete for the declared loss responsibility**, not merely one convenient loss statistic.

No TU-1–TU-4 dependency direction, finite theorem result, or claim ceiling is expanded by this patch.

---

## 1. Scientific contract: `D_req` is not realized evidence

The canonical scientific contract is henceforth written

\[
\boxed{
\mathcal C=(\Gamma,\mathcal H,\Theta,\mathcal D_{\rm req};T).
}
\]

The subscript `req` is semantic, not cosmetic.

### 1.1 `D_req` — EvidenceRequirement

`D_req` is a **contract-level requirement**. It specifies the observation, experiment, calibration, failure, reliability, and reporting conditions under which a distinction or target would count as scientifically resolvable/reportable.

It is declared before the realized observation record is known.

Examples of content that may live in `D_req` include:

- which experiment or observation family is admissible;
- sensitivity/specificity or calibration requirements;
- allowed failure dependence;
- false-resolution or risk ceilings;
- minimum evidence resolution needed for a requested report;
- which record distinctions must be preserved by the scientific workflow.

`D_req` may therefore constrain the **scientific responsibility** represented in the contract, but it is not itself an observed dataset.

### 1.2 `y` — ObservationRecord

A realized observation is written

\[
y\in\mathcal Y_{\mathcal D_{\rm req}}.
\]

It is produced under the declared observation/reliability architecture.

### 1.3 `E_y^{D_req}` — RealizedEvidenceClass

The realized evidence-compatible world set is

\[
\boxed{
E_y^{\mathcal D_{\rm req}}
=
\{\omega\in\Omega:
\omega\text{ is compatible with }y
\text{ under }\mathcal D_{\rm req}\}.
}
\]

This is an **epistemic result** obtained after observation.

Therefore

\[
\boxed{
\mathcal D_{\rm req}
\neq
E_y^{\mathcal D_{\rm req}}.
}
\]

The first is a requirement/architecture; the second is the remaining compatible-world class after a realized record.

## 2. Structural state versus realized identification

The v0.5 principle

\[
\text{RequiredState}
\neq
\text{EvidenceClass}
\neq
\text{Report}
\]

is retained, but its notation is sharpened.

Let

\[
J_{\mathcal C}
\]

be the required-state partition induced by the declared scientific responsibility. Let

\[
E_y^{\mathcal D_{\rm req}}
\]

be the realized evidence partition/class after observing `y`.

Then:

### Full-state identification

A deterministic full-state label is licensed only when the realized evidence resolves the required partition:

\[
\boxed{
J_{\mathcal C}\preceq E^{\mathcal D_{\rm req}}.
}
\]

### Target-only identification

Even if

\[
J_{\mathcal C}\not\preceq E^{\mathcal D_{\rm req}},
\]

a target may still be reportable if `T` is constant on each realized evidence class relevant to the report.

### Non-creation rule

Changing or refining realized evidence can change **what is identified**. It does not retroactively create a structural world distinction that was absent from the declared scientific responsibility.

Thus the correct direction is

```text
contract responsibility -> required distinctions
realized observation     -> identified distinctions
required + identified    -> licensed report
```

and never

```text
realized data -> ontic distinction by decree
```

## 3. The `C_{D,T}` notation in CREST-compatible prose

Where the frozen v0.5 documents use a closure such as

\[
C_{D,T},
\]

v0.5.1 reads it as

\[
\boxed{C_{\mathcal D_{\rm req},T}}
\]

meaning the **required resolution/reportability obligation encoded by the declared evidence/reliability contract and target**.

It must not be read as a closure generated by the accidental contents of the realized sample `y`.

The realized evidence partition remains a separate object:

\[
E_y^{\mathcal D_{\rm req}}.
\]

This preserves the v0.5 firewall that evidence licenses or identifies but does not create ontic distinctions.

## 4. Loss contract and contract-complete response signature

The second clarification concerns `LossResponseSignature`.

A single scalar such as

- eventual loss probability;
- one threshold-crossing time;
- one-horizon survival probability;
- one intervention response;

is **not automatically** the loss response signature of the Theory Universe.

Let the declared loss contract be

\[
\mathcal C_L
=
(\Gamma_L,\mathcal H_L,\Theta_L,\mathcal D_{L,\rm req};T_L).
\]

Define an index family

\[
\mathcal Q_L
\]

containing every loss-relevant query context required by that contract. Depending on the contract this may include combinations of:

- allowed actions/interventions from `Gamma_L`;
- future horizons or stopping rules;
- history/transport semantics from `H_L` when they are part of the retained scientific meaning;
- retained mechanism alternatives from `Theta_L` when response robustness across them is required;
- target/report distinctions required by `(D_{L,req},T_L)`.

The **full loss-contract response signature** is

\[
\boxed{
\Sigma_{\mathcal C_L}(\omega)
=
\bigl(R_q(\omega)\bigr)_{q\in\mathcal Q_L},
}
\]

where each `R_q` is the deterministic response, response distribution, trajectory law, stopping-time law, or other response object required for query context `q`.

The exact contents of `Q_L` are contract-relative. The requirement is completeness with respect to the declared loss responsibility, not maximal description of the world.

## 5. LossGeneratingState under v0.5.1

The loss-generating equivalence relation is

\[
\omega\sim_L\omega'
\iff
\Sigma_{\mathcal C_L}(\omega)
=
\Sigma_{\mathcal C_L}(\omega').
\]

Hence

\[
\boxed{
Q_L
=
\Omega/\ker\Sigma_{\mathcal C_L}.
}
\]

`LossGeneratingState` is therefore **target/contract complete**, not synonymous with equality of one chosen loss summary.

### CREST compatibility

On a declared common carrier, if `Sigma_{C_L}` exhaustively encodes every distinction required by the loss-specialized CREST contract, then

\[
\boxed{
Q_L\cong S_{\mathcal C_L}.
}
\]

If the chosen response signature omits a contract-required distinction, then only

\[
Q_L^{\rm candidate}
\]

has been constructed, and it must not be promoted to the full `LossGeneratingState`.

This is the key anti-contradiction rule.

## 6. TU-3 under the clarified signature

TU-3 remains a representation-faithfulness theorem/firewall.

A projection

\[
\pi:\Omega_A\to\Omega_B
\]

is loss-faithful only if the **full contract-complete loss signature** factors through it:

\[
\boxed{
\Sigma_{\mathcal C_L}^{A}
=
\bar\Sigma_{\mathcal C_L}\circ\pi.
}
\]

Checking only one marginal loss statistic is insufficient unless that statistic has first been shown to exhaust the declared loss responsibility.

Therefore TU-3 still permits arbitrary nuisance-state inflation, but only coordinates irrelevant to the whole declared loss response may be discarded.

## 7. TU-4 under the clarified signature

TU-4 continues to distinguish loss state from warning-evaluation state.

Let the full warning response required by the warning contract be

\[
\Sigma_G(\omega).
\]

Then the warning-evaluation quotient is generated by the joint signature

\[
\boxed{
\Sigma_W(\omega)
=
\bigl(\Sigma_{\mathcal C_L}(\omega),\Sigma_G(\omega)\bigr).
}
\]

Thus

\[
Q_L\preceq Q_W.
\]

Equality holds exactly when the required warning response factors through the full loss-contract state.

The clarification strengthens, rather than weakens, the firewall:

```text
same scalar loss statistic
    does not imply
same LossGeneratingState

same LossGeneratingState
    does not imply
same WarningEvaluationState
```

## 9. What this patch changes and does not change

### It changes

- ambiguous notation `D` is canonically read as `D_req` when it denotes a contract component;
- realized evidence is canonically written separately as `E_y^{D_req}`;
- `LossResponseSignature` is canonically interpreted as a full contract-complete loss-response signature `Sigma_{C_L}`.

### It does not change

- the v0.5 Reality/World/State separation;
- CREST's source-owned common-carrier state construction;
- CCOC, MLTR, MRM, CED, or RACH theorem ownership;
- TU-1 revision results;
- TU-2 learning/licensing orthogonality;
- TU-3's finite factorization logic;
- TU-4's warning-state refinement/portability logic;
- the theorem dependency DAG;
- any empirical state claim.
