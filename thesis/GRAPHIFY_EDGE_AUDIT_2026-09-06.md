# Graphify edge audit — 2026-09-06

## Conclusion

The Graphify graph does **not** support a single `state` spine and does **not** support the hard sequence

```text
eco-genetic -> CREST -> observation design
```

The current curated graph instead contains three major research streams connected by a small number of typed junctions and incomplete bridges.

The correct dissertation reading is therefore:

```text
                 Eco-genetic series
              mechanism -> loss -> warning
                       \
                        \  partial / bounded bridge only
                         \
CREST series ------------- junctions ------------- microdonta/RACH learning series
future/history/mechanism      |                    causal set -> next observation
        -> CREST              |
        + CED licensing ------+
```

The three research chapters may be displayed in any editorial order. Their order is not a theorem dependency.

## 1. Graph freshness caveat

`universe/registry.json` reports `generated_on = 2026-08-25`. It therefore predates the later publication split of the legacy `microdonta` surface into:

- `zuizui0223/boundary` — structural/channel identifiability;
- `zuizui0223/mrod` — admissible mechanism regions and next-observation design.

Until the registry is regenerated, cross-community edges involving `repo:microdonta` must be read as legacy programme edges, not as current runtime dependencies of Boundary or MROD.

```text

  --mechanistic_parent_to_condition_extension-->

```

Contract: pinned scientific commit, separate code/evidence ledgers.

This direction matches the scientific programme:


The Worldline Atlas independently gives the hard junction:

```text
LossGeneratingState <= WarningEvaluationState
```

- The eco-genetic-to-CREST relation does not justify collapsing the two series.

## 4. CREST series — hub and spoke, not a linear chapter chain

The registry contains four direct repo edges into `crest`:

```text
repo:ccoc --conceptual_obstruction_input--> repo:crest
repo:mltr --conceptual_obstruction_input--> repo:crest
repo:mrm  --conceptual_obstruction_input--> repo:crest
repo:ced  --downstream_evidence_licensing--> repo:crest
```

The first three are parallel structural inputs:

- CCOC: future/composition obstruction;
- MLTR: inherited-history / semantic transport obstruction;
- MRM: retained-mechanism response obstruction.

They do not prove one another.

CED is different. It is an evidence/reportability junction. In the canonical universe flow, CREST-required distinction `J`, evidence/reliability `D`, and target `T` all enter CED. Thus CED is strongly connected to CREST but is not ontologically owned by CREST.

Graphify clustering confirms this distinction:

- Community 4: `CREST and Evidence Licensing`;
- Community 7: `Transport and Mechanism Robustness` (MLTR + MRM);
- CCOC lies on the future/open-composition side rather than collapsing into either community.

This supports one CREST flagship **only if** the companion theories are treated as typed inputs/supporting modules, not five coequal headline theorem families.

## 7. The actual Graphify junctions

### Required-State Junction

Worldlines:

```text
capability + future + history + mechanism
```

Condition: compatible shared carrier or faithful common lift plus typed response obligations.

This is the proper place to combine CREST/CCOC/MLTR/MRM results.

### Knowledge Junction

Worldlines:

```text
capability + evidence + learning
```

Condition: required state, evidence classes, causal programmes, and report target must be typed on compatible model worlds.

This is where CREST/CED and microdonta/RACH can eventually meet. It is explicitly a **junction condition**, not a current identity theorem.

### Loss-Warning Junction

```text
LossGeneratingState <= WarningEvaluationState
```

This is the strongest cross-result directional dependency and belongs inside the eco-genetic series.

### Reality-to-Theory Junction

Every model-world line returns to empirical admission and claim ceilings. No theorem-family integration itself establishes natural-system validity.

## 8. Corrected publication architecture

The edge-faithful default is **three strong papers**, not one mega-paper and not one paper per repository.

1. **Eco-genetic series** — mechanistic parent -> loss-generating domain -> warning validity / portability.
2. **CREST series** — CREST hub with CCOC/MLTR/MRM typed obstruction inputs and CED as licensing junction; companion proofs can move to SI.
3. **microdonta/RACH series** — Boundary + MROD: identifiability -> admissible ambiguity -> next-observation design.

Cross-series incomplete bridges should be discussed in the dissertation synthesis rather than used to merge papers prematurely.
